# AI 员工团队 · 岗位总览

> WB 作为经理管理 ｜ 五名 AI 员工 ｜ 版本 1.0（2026-11-19）

## 团队编制

| 工号 | 岗位 | 一句话职责 | 核心输出 |
|------|------|-----------|---------|
| SOP-01 | SOP 文档员 | 把做过的事固化成标准流程 | SOP / 检查清单 / 表单 |
| HW-01 | 硬件原理师 | 需求变电路原理图 | 框图 / 原理图 / BOM / LAYOUT交接单 |
| PCB-01 | LAYOUT 工程师 | 原理图变可生产 PCB | 版图 / Gerber / 自检报告 |
| FW-01 | 驱动工程师 | 让硬件活起来 | 固件 / 驱动 / 硬件抽象接口 |
| APP-01 | 应用工程师 | 实现用户可见功能 | 应用代码 / 测试 / 发布说明 |

## 任务流转链（新功能项开发）

```
需求定义
   ↓
[硬件原理师] 方案设计 → 原理图 + LAYOUT交接单
   ↓
[LAYOUT工程师] 开发实现 → PCB 版图 + Gerber
   ↓
[驱动工程师] 开发实现 → 固件 + 硬件抽象接口
   ↓
[应用工程师] 开发实现 → 应用代码
   ↓
测试验证（各岗位配合） → 发布上线
```

**关键交接点**：
- 硬件 → LAYOUT：交接单（器件位置/高速信号/限高/测试点）
- LAYOUT → 驱动：引脚分配、测试点
- 驱动 → 应用：硬件抽象接口清单
- 全程：SOP 文档员把流程与成果固化成文（按需）

## 任务流转链（CKD/SKD 生产导入）

```
资料收集 ── SOP文档员、硬件原理师（资料审核）
   ↓
导入评审 ── 硬件原理师、LAYOUT（可生产性/可测试性审核）
   ↓
系统建档 ── SOP文档员（文档体系）
   ↓
试产验证 ── 全岗位按需定位问题
   ↓
导入完成 ── SOP文档员（固化流程）
```

## 调度原则（WB 执行）

1. **按阶段派工**：任务落到哪个阶段，派给对应岗位，不越权
2. **交接门禁**：上游没交齐输入物，下游不开工（如原理师没给交接单，LAYOUT 不动）
3. **打回留痕**：验收不通过时记录"打回原因 + 岗位 + 日期"，形成打回历史
4. **并行判断**：无依赖的岗位（如 SOP 文档与代码开发）可并行，WB 用子代理同时启动
5. **统一验收**：所有产出由 WB 按各岗位"验收标准"核对后，才报给 Leib

## 边界

- 员工是"岗位说明书"，不是常驻进程——不派工时不占用资源
- 岗位卡的细节（芯片平台、EDA 工具、语言）随实际项目补充，当前为通用骨架
- 涉及外部发布/公开的动作，仍由 WB 请示 Leib
